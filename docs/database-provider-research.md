# Database options for many small apps

Checked September 14, 2026. This is a pricing and fit comparison, not a migration plan or a snapshot of any provider account. Prices are USD before tax; free tiers and overages can change.

## Recommendation

**Use Neon as the default for new Vercel/Next.js apps, including NinetyNinety if its data is to remain relational.** Its current Free plan allows **100 projects**, each with **0.5 GB storage and 100 compute-unit hours/month**; idle compute scales to zero after five minutes. The Launch plan is usage-based with no stated subscription minimum: **$0.106/compute-unit hour + $0.35/GB-month** of storage, plus applicable transfer/branch charges. This solves the “a bunch of quiet apps” problem without buying a separate always-on instance for each one. It also preserves Postgres SQL, offers an official Vercel integration that provisions credentials, and has a provider-run MCP server plus a Codex plugin for agent-assisted schema/branch work. The tradeoff is a short free restore window (up to six hours or 1 GB of changes) and the need to replace Supabase-specific Auth, Storage, and Data API pieces if an app uses them. [Neon pricing](https://neon.com/pricing), [Neon 100-project announcement](https://neon.com/docs/changelog/2025-12-19), [Neon on Vercel](https://vercel.com/marketplace/neon/neon), [Neon MCP](https://neon.com/docs/ai/neon-mcp-server), [Neon Codex plugin](https://neon.com/docs/ai/ai-codex-plugin), [Supabase platform overview](https://supabase.com/docs/guides/getting-started/architecture)

**Keep Turso as the alternative when low, predictable portfolio cost matters more than Postgres compatibility.** Its Free plan also allows **100 databases**, but with a **shared 5 GB storage** allowance, 500 million rows read/month, and 10 million rows written/month. The Developer plan is **$5.99 month-to-month** (or $4.99/month billed yearly), allows unlimited databases, and includes 9 GB storage. Idle databases cost only their storage. Its remote TypeScript SDK works in Vercel Functions; the Vercel Marketplace can inject credentials. This is attractive for new, simple apps, but a Supabase/Postgres schema and client calls need a SQLite/libSQL rewrite. Turso Cloud currently documents libSQL/SQLite compatibility; do not assume its newer embedded Turso engine features are all in the cloud service. [Turso monthly pricing](https://turso.tech/pricing?frequency=monthly), [Turso yearly pricing](https://turso.tech/pricing), [Turso TypeScript SDK](https://docs.turso.tech/sdk/ts/quickstart), [Turso Cloud docs](https://docs.turso.tech/turso-cloud), [Turso on Vercel](https://vercel.com/marketplace/tursocloud)

| **Neon** | 100 projects; 0.5 GB and 100 compute-unit hours **per project**; idle compute scales to zero. | **$0 within free limits**. Launch has no fixed subscription minimum, but storage and active compute are metered. | Best Postgres and Vercel/AI-agent fit. Watch restore window, free transfer quota, and active compute. [Pricing](https://neon.com/pricing), [usage-based plan explanation](https://neon.com/blog/new-usage-based-pricing) |
| **Turso Cloud** | 100 databases; 5 GB storage and row allowances shared by the plan. | **$0 within free limits**, or **$5.99/month** Developer month-to-month for unlimited databases within included usage. | Lowest simple paid portfolio price; SQLite/libSQL means a real migration from Postgres. [Monthly pricing](https://turso.tech/pricing?frequency=monthly), [cloud engine](https://docs.turso.tech/turso-cloud) |
| **Cloudflare D1** | 10 databases; 500 MB each, 5 GB total; 5M rows read/day and 100K written/day. | **$5/month Workers Paid** for up to 50,000 databases, with generous included D1 reads/writes/storage before overages. | Excellent database count and true query-based scale-to-zero, but less direct from an existing Vercel app: Cloudflare recommends a Worker API in front of D1 for access outside Workers; its REST API is mainly administrative and subject to global API rate limits. Free daily row limits now fail closed when exceeded. [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [external access guide](https://developers.cloudflare.com/d1/tutorials/build-an-api-to-access-d1/), [limit enforcement](https://developers.cloudflare.com/changelog/product/d1/) |
| **PlanetScale Postgres** | No free plan. | **At least ~$50/month** for ten separate $5/month single-node databases, before variable charges. | Good Postgres product, but its per-database cluster floor misses this cost target. [Plans](https://planetscale.com/docs/planetscale-plans), [Postgres pricing](https://planetscale.com/docs/postgres/pricing) |

These are *floor illustrations*, not quotes. Neon paid usage depends on how long each compute is awake; Turso/D1 usage and storage are shared at the account or plan level. For example, ten Neon databases using 0.1 GB each and 2 compute-unit hours each in a month would cost about **$2.47** on Launch before other charges: `10 × (0.1 × $0.35 + 2 × $0.106)`. That is an illustrative calculation from the published rates, not a forecast. [Neon pricing](https://neon.com/pricing), [Turso pricing](https://turso.tech/pricing?frequency=monthly), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/)

## How this applies to NinetyNinety

The repo currently has a Supabase client in `src/lib/supabase.ts`, a starter page in `src/app/page.tsx`, and no implemented Vercel `/api/ingest` route. `PROJECT.md` sketches a Postgres schema, but it is aspirational rather than proof of the live database’s schema. A live project listing on September 14 showed `ninetyninety` and `ruby-warrior` inactive and only `foxops` active, so restoring `ninetyninety` may now fit the two-active-project Free limit; no restore was attempted during this research. That makes **Neon the lower-rewrite default for the broader portfolio**, not an automatic migration: first recover/export the actual Supabase data and schema, decide whether any Supabase-only features are really in use, then implement the authenticated Vercel route and repoint the GitHub workflow. No provider switch by itself fixes the missing endpoint. [Supabase Free limit](https://supabase.com/pricing)

Before choosing, confirm the intended number of apps, whether Auth/Storage are needed, and acceptable recovery window. In particular, Turso’s Vercel Marketplace listing still says “500 Free,” while Turso’s own current pricing page says **100 Free**; use Turso’s pricing page for budgeting until the discrepancy is resolved. [Turso pricing](https://turso.tech/pricing?frequency=monthly), [Turso Vercel listing](https://vercel.com/marketplace/tursocloud)
